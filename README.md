# Практическая работа №4 — PHP. Основы языка, запросы и обработка HTML-форм

## Описание

Адаптивная панель сотрудников. Приложение читает сотрудников из `data/employees.csv`, показывает таблицу, позволяет фильтровать её через GET и добавлять запись через POST-форму. PHP проверяет данные на сервере и выводит значения безопасно с помощью `htmlspecialchars`.

## Требования

- PHP 8.0 или новее
- Браузер
- Терминал для запуска встроенного PHP-сервера

## Структура проекта

```text
trpo-pr04-student/

```

## Запуск

Открой терминал в папке проекта и выполни:

```bash
php -S localhost:8000 -t public
```

Затем открой в браузере:

http://localhost:8000

Важно: PHP-проект нельзя корректно запустить простым открытием `index.php` как файла. Нужен PHP-сервер.

## Что реализовано

- Вывод версии приложения и текущей даты средствами PHP.
- Массивы, условия, циклы и пользовательские функции.
- Чтение CSV через `fgetcsv` с разделителем `;`.
- Функции `loadEmployees`, `normalizeEmployee`, `validateInput`, `loadFormCases` и `e`.
- POST-форма с четырьмя полями: имя, отдел, опыт работы, email.
- Серверная проверка обязательных значений, длины имени, email и диапазона опыта от 0 до 60 лет.
- При ошибках значения остаются в форме, сообщения отображаются рядом с полями.
- Все вводимые пользователем строки экранируются через `htmlspecialchars`.
- GET-фильтр сотрудников по отделу.
- Отображение тестовых сценариев из `form_cases.json`.
- Адаптивная верстка для мобильных экранов и таблица с горизонтальной прокруткой на маленьких экранах.

## Проверка

1. Открой страницу: должны отображаться сотрудники из CSV.
2. Отправь пустую форму: должны появиться ошибки, приложение не должно падать.
3. Введи опыт `-2`: должна появиться ошибка диапазона.
4. Введи некорректный email: должна появиться ошибка email.
5. Заполни все поля корректно: сверху появится подтверждение, новая запись добавится в таблицу текущего ответа.
6. Выбери отдел в фильтре: таблица покажет только сотрудников этого отдела. Нажми «Сбросить», чтобы вернуть все записи.
7. Сравни три тестовых сценария на странице с `data/form_cases.json`.

## GET и POST

GET передаёт параметры в адресной строке и здесь используется для фильтрации таблицы. POST передаёт данные формы в теле запроса и используется для добавления сотрудника.

## Безопасный вывод

`htmlspecialchars` преобразует специальные HTML-символы в безопасные представления, поэтому введённый пользователем текст не интерпретируется браузером как HTML-разметка.

## Пример содержательных коммитов

```text
chore: create project structure
feat: load employees from CSV
feat: add POST form and server validation
feat: add GET department filter and responsive layout
docs: describe setup and test scenarios
```

Новая запись добавляется только в текущий ответ приложения и не записывается обратно в CSV. Для учебного задания это позволяет проверить полный цикл формы без дополнительного механизма хранения.
